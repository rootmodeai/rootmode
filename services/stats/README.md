# rootmode stats collector

A small FastAPI service that workers report to, and the explorer reads from —
and which serves the site as well, so `rootmode.ai` is one box with one
certificate and no `stats.` subdomain to stand up.

It is **centralised**, and worth being honest about: this is the one piece of
rootmode that is a server everyone talks to. The network does not need it —
jobs never touch it, clients never contact it, and a worker that ignores it is
a full member of the network. It exists so the explorer can show a number.

## What it does and does not hold

| Collected | Never collected |
|---|---|
| Request and image counts per worker | Prompts |
| Token totals the inference server reported | Answers |
| What a worker charged | Who asked (client peer ids) |
| A worker's label, models, capabilities | Conversations, of any kind |
| A country, from the connection or the operator | The address itself |

The address a report arrives from is resolved to a country and dropped. If
`ROOTMODE_IP_SALT` is set, a salted one-way hash is kept so repeat reports can
be recognised as one machine; without a salt, not even that — an unsalted hash
of an IPv4 address is brute-forced in seconds, and a false sense of anonymity
is worse than none.

Geolocation is a **local** GeoLite2 database, never a lookup API. Calling one
would hand a third party the addresses of every worker on the network, which is
a bigger leak than the thing being measured.

## One box, one process

The container ships the site as well as the API, so a single VPS serves both:

| path | what |
|---|---|
| `/`, `/worker`, `/explorer`, `/protocol`, `/discovery`, `/brand` | `apps/web` pages |
| `/report` | workers post here (`/v1/report` is the same handler) |
| `/stats.json` | the explorer reads here (`/v1/stats.json` likewise) |
| `/healthz` | liveness |

Because the page and its numbers share an origin, the explorer's fetch is not
a cross-origin request at all — no CORS to configure, no second host, no second
box. `ROOTMODE_WEB_DIR=""` (or a missing directory) turns the site off and
leaves a bare API.

Put a TLS terminator in front and you are done. Two lines of Caddyfile:

```
rootmode.ai {
    reverse_proxy 127.0.0.1:8080
}
```

One DNS record, one certificate, one VPS. Workers post to
`https://rootmode.ai/report`; the explorer reads
`https://rootmode.ai/stats.json` from its own origin.

## Running it

```sh
# From the repo root: the build needs apps/web as well as the service.
docker build -f services/stats/Dockerfile -t rootmode-stats .
docker run -d -p 8080:8080 \
  -v rootmode-stats:/var/lib/rootmode \
  -e ROOTMODE_IP_SALT="$(openssl rand -hex 16)" \
  -e ROOTMODE_CORS="https://rootmode.ai" \
  rootmode-stats
```

Or directly:

```sh
cd services/stats
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8080
```

| variable | default | |
|---|---|---|
| `ROOTMODE_STATS_DB` | `/var/lib/rootmode/stats.db` | SQLite file |
| `ROOTMODE_IP_SALT` | — | enables the one-way address hash; rotate to forget |
| `ROOTMODE_GEOIP_DB` | `/var/lib/rootmode/GeoLite2-Country.mmdb` | optional, local |
| `ROOTMODE_REQUIRE_SIG` | `true` | leave on; off means anyone can invent a node |
| `ROOTMODE_TRUST_PROXY` | `false` | on only behind a proxy you control |
| `ROOTMODE_MAX_REPORTS_PER_HOUR` | `240` | per peer id |
| `ROOTMODE_CORS` | `*` | origins allowed to read the stats document |

## Endpoints

**`POST /report`** — one window of counters from one worker. The body is
the shape in `crates/rootmode-worker/src/stats.rs`, signed with the node's key
over canonical JSON with `sig` removed. Refused with `401` if the signature
does not match the `peer_id`, `422` if the numbers are outside sane bounds,
`429` if that key is reporting too often.

**`GET /stats.json?days=120`** — exactly what `/explorer`
renders: `days`, `models`, `workers`, `updated`. Cached for a minute.

Both are also served under `/v1/…`, for the day the shape changes and two
versions have to be live at once.

## Point the explorer at it

Nothing to do when this service serves the page: the explorer reads
`/stats.json` from its own origin by default. Only needed when the site lives
somewhere else than its collector:

```html
<body data-stats="https://example.com/stats.json">
```

With no collector answering, the page falls back to its built-in sample and
says so in a banner.

## Tests

```sh
cd services/stats && pytest -q
```

They cover the parts that fail quietly: an unsigned report, a report signed by
the wrong key, edited numbers, absurd counts, throttling, and — the one that
would otherwise only surface in production — a real report generated by the
Rust worker (`cargo run -p rootmode-worker --example signed_report`) verifying
against this service's canonical JSON.

## Two known limits

**Per-model tokens are estimated.** A report carries the node's model list and
its totals, not a count per model, so the "most-asked models" chart shares a
node's tokens evenly across what it serves. Per-model counters in the worker
are the fix; cleverer arithmetic here would only be a better-dressed guess.

**"People asking" counts workers, not people.** The collector never sees a
client, so what the explorer plots is reporting workers, new and returning. It
is labelled as such on the page, and it cannot be made into a user count
without clients reporting — which would mean collecting the one thing this
design refuses to.
