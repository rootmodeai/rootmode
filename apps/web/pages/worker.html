For operators

Run a worker.

A worker is what turns a machine with GPUs into a peer on the network. One compose file, pointed at the vLLM or ComfyUI you already run. It needs no GPU access of its own, and there's no application or approval queue — start it and you're serving.

Start here Full documentation

Before you start

What you need on the box.

The worker doesn't hold models and doesn't touch your GPUs. It speaks to an inference server you already run, over HTTP.

Docker

And a clone of the repo. docker compose up is the whole start. Or a Rust toolchain, if you'd rather build from source.

vLLM, for text

Any OpenAI-compatible endpoint. Typically 127.0.0.1:8000. Comment it out in .env if this box only serves images.

ComfyUI, for images and video

Uncomment it in .env and every checkpoint installed is served — still images, and video models such as MiniMax if they're on the box. Export a workflow instead when your pipeline has a shape of its own.

Quickstart

Serving in about ten minutes.

Clone it and name the endpoints

The compose file is the same on every box — Spark, A100, H100, or a machine whose cards sit behind a remote URL. .env is the only thing that changes. Uncomment vLLM, ComfyUI, or both; at least one is required. A price is one more line; leave it out and you advertise as free.

setup
$ git clone https://github.com/rootmodeai/rootmode
$ cd rootmode
$ cp .env.example .env
.env
# OpenAI-compatible server. Comment out if this box only serves images.
ROOTMODE_VLLM=http://127.0.0.1:8000
# ROOTMODE_VLLM_PRICE=0.15          # per million tokens, every model

# ComfyUI. Uncomment to serve images too, or instead of vLLM.
# ROOTMODE_COMFYUI=http://127.0.0.1:8188
# ROOTMODE_COMFYUI_PRICE=0.02       # per image, every checkpoint
# ROOTMODE_COMFYUI_PRICES=sdxl=0.02,krea2-turbo=0.08

Start the worker

The container talks to your inference server over HTTP, so it needs no GPU access itself. Host networking is the simplest thing that works on Linux.

run
$ docker compose up -d --build
Keep the volume.

/var/lib/rootmode holds the node's key, and that key is its identity. Lose it and your peer id changes — every client that pinned you stops recognising the node.

Check what it says

On each start it writes a worker.toml from the environment and prints it, then advertises exactly what the box actually serves. A price changed in .env takes effect on restart.

docker compose logs -f
INFO rootmode worker v0.1.0
INFO peer_id=ef9084b8a01c18be4b75fb7e0b72b7b4d57b5be9…
INFO listening on ws://0.0.0.0:9944
INFO caps: [llm]  max_concurrent: 2
INFO   meta-llama/Llama-3.1-8B-Instruct (llm)
INFO this node is its own entry point — give a client one of:
INFO   /ip4/192.168.1.50/tcp/4101/p2p/12D3KooWR3Tjk…

Connect a client to it

On the same network, the desktop app finds it on its own — it appears on the peers screen marked discovered. From elsewhere, add ws://<host>:9944 by hand, and paste the peer id into the public key field to pin it.

To check a node without the desktop app at all:

smoke test
$ cargo run -p rootmode-worker --example submit -- \
    ws://127.0.0.1:9944 "what is a peer?"

Configuration

The settings worth knowing.

Set them in .env next to the compose file. Mount your own worker.toml and set ROOTMODE_CONFIG to its path — then none of these apply.

VariableDefaultWhat it does
ROOTMODE_VLLM—OpenAI-compatible endpoint for text. Comma-separate if this box has more than one.
ROOTMODE_VLLM_PRICE—What you charge per million tokens, for every model that server reports. Unset is advertised as free.
ROOTMODE_VLLM_PRICES—Optional per-model overrides: id=0.40,id=0.10
ROOTMODE_COMFYUI—ComfyUI endpoint for images and video. Pointing at it is enough — every installed checkpoint is advertised.
ROOTMODE_COMFYUI_PRICE—What you charge per image, for every checkpoint. Unset is advertised as free.
ROOTMODE_COMFYUI_PRICES—Optional per-checkpoint overrides: sdxl=0.02,krea2-turbo=0.08
ROOTMODE_CURRENCYUSDCurrency for the prices above
ROOTMODE_PAYOUT—Address that receives your 90% when a job settles.
ROOTMODE_POT—RootmodePot contract. Empty means this node is not charging on-chain.
ROOTMODE_CHAIN_ID8453Settlement chain. Base is 8453.
ROOTMODE_RPC—JSON-RPC URL used to check the lock and to submit spend tickets.
ROOTMODE_PAY_KEY—Ethereum private key (secp256k1, 32-byte hex) this node signs settle with. Leave it in .env, not in a config file you share. Needs a little ETH for gas. Does not have to be the payout address.
ROOTMODE_PAY_SENDER—Address that posts settle. Derived from the key if you set one.
ROOTMODE_BOOTSTRAP—Entry points to join, comma-separated
ROOTMODE_P2P_EXTERNAL—Address to advertise, if not what it binds
ROOTMODE_LABELhostnameThe name clients see
ROOTMODE_LISTEN0.0.0.0:9944WebSocket address
ROOTMODE_MAX_CONCURRENT2Jobs to run at once
ROOTMODE_REQUIRE_SIGNATUREfalseRefuse unsigned submissions
ROOTMODE_ALLOW_PEERS—Only these client peer ids may submit
ROOTMODE_RELAYtrueAsk for a relay slot — needed behind NAT

A price without a pot is only a sticker. To get paid, set ROOTMODE_POT, ROOTMODE_RPC, ROOTMODE_PAYOUT and ROOTMODE_PAY_KEY. The client locks funds before the GPU runs; this node signs and submits the spend ticket afterwards. 90% to your payout address, 10% to the network.

Behind NAT, or publishing ports instead of using host networking? Set ROOTMODE_P2P_EXTERNAL to the address other peers should dial — otherwise they discover the node and then can't reach it.

Your machine, your rules

What a client can and can't do to your box.

Nothing a client sends is executed A job picks a workflow you declared and fills parameters you declared. That is the entire surface — no job field reaches a process spawn.
You choose the models on offer The worker holds none of its own. It advertises what your inference server actually serves, and nothing else can be requested.
You can restrict who submits at all Require signed submissions, or list the exact client peer ids allowed. Everything else is refused before it runs.
For images, a prompt and a checkpoint — nothing else A client picks one of the checkpoints you have installed and sends words. It can't send a graph, add a node, or reach a setting you didn't offer. Export a workflow and even the checkpoint is fixed.
Stop means stop docker compose down and the node is off the network. There's no notice period and nothing to cancel.
You're responsible for what your node serves.

Workers run models the operator chose, on hardware the operator owns. Local law and acceptable use are yours to observe.

Going further

When one node becomes several.

A lone worker is its own entry point — a client pointed at it discovers what it serves. Once several nodes need to find each other, run a bootstrap node and point them all at it. It's an entry point and a relay for NAT'd nodes, never a registry, never an authority, and never in the path of a job.

bootstrap node
$ docker build -f docker/Dockerfile.bootstrap -t rootmode-bootstrap .
$ docker run -d -p 4001:4001 -v rootmode-bootstrap:/var/lib/rootmode \
    rootmode-bootstrap --announce /ip4/<this host>/tcp/4001

Run several. Any node can be one. A worker joins through ROOTMODE_BOOTSTRAP in .env, or through the entry points compiled into the binary.
